# Auth Code Flow with PKCE — TradeStation

> **Note:** This is not the default flow. Contact Client Experience to request
> it. For the standard flow and API key defaults, see
> [`auth-fundamentals.md`](auth-fundamentals.md).

## Overview

The Authorization Code Flow with Proof Key for Code Exchange (PKCE) is
designed for public clients — native apps and single-page apps — where a
`client_secret` cannot be kept confidential.

Instead of a `client_secret`, PKCE uses a two-value proof:

| Value | Description |
|---|---|
| `code_verifier` | Random string (43–128 chars) generated by the client at login time. Never sent to the server during the authorization step. |
| `code_challenge` | SHA-256 hash of the `code_verifier`. Sent to the server during the authorization step. |

A malicious actor who intercepts the `authorization_code` cannot exchange it
for tokens without the original `code_verifier`.

## Step-by-Step (Generic / Manual Implementation)

### Step 1 — Redirect the user for authentication

Build and redirect to the authorization URL:

```
https://signin.tradestation.com/authorize
```

Query string parameters:

| Parameter | Required | Value |
|---|---|---|
| `response_type` | required | `code` |
| `client_id` | required | Your API Key. |
| `audience` | required | `https://api.tradestation.com` |
| `redirect_uri` | required | Must match one of the Allowed Callback URLs on your API key (see below). |
| `scope` | required | Space-separated, case-sensitive. `openid` always required; add `offline_access` for Refresh Tokens. Example: `openid profile offline_access MarketData ReadAccount Trade` |
| `code_challenge` | required | SHA-256 hash of the `code_verifier`. |
| `code_challenge_method` | required | `S256` |
| `state` | recommended | Random opaque string — used to prevent CSRF attacks. |
| `prompt` | optional | Set to `login` to always show the login screen, even if a session already exists. |

Default Allowed Callback URLs (localhost, for development):

```
http://localhost
http://localhost:80
http://localhost:3000
http://localhost:3001
http://localhost:8080
http://localhost:31022
```

Example authorization URL:

```
https://signin.tradestation.com/authorize
  ?response_type=code
  &client_id=YOUR_CLIENT_ID
  &redirect_uri=http://localhost:8080
  &audience=https://api.tradestation.com
  &state=STATE
  &scope=openid offline_access profile MarketData ReadAccount Trade
  &code_challenge=MChCW5vD-3h03HMGFZYskOSTir7II_MMTb8a9rJNhnI
  &code_challenge_method=S256
```

### Step 2 — User logs in and grants consent

The user is shown the TradeStation login page. After logging in, they see a
consent dialog to approve the requested scopes. This dialog appears on every
login.

When using a `localhost` `redirect_uri`, a **second** consent dialog may
appear on the first login or if access was previously denied — once approved,
it is not shown again for the same API key / login combination unless the
requested scopes change.

If the user declines, Auth0 redirects back to `redirect_uri` with:

```
http://example.com/?error=access_denied&error_description=User%20declined%20authorization
```

### Step 3 — Receive the Authorization Code

On successful authentication, Auth0 redirects to `redirect_uri` with the
`code` and `state` in the query string:

```
HTTP/1.1 302 Found
Location: http://localhost:8080?code=AUTHORIZATION_CODE&state=xyzABC123
```

> The length of the Authorization Code is variable.

### Step 4 — Exchange the Authorization Code for tokens

POST to the token endpoint. Use `content-type: application/x-www-form-urlencoded`.
Send the original `code_verifier` (not the hash) instead of a `client_secret`.

**Token URL:**

```
https://signin.tradestation.com/oauth/token
```

Parameters:

| Parameter | Required | Value |
|---|---|---|
| `grant_type` | required | `authorization_code` |
| `client_id` | required | Your API Key. |
| `code` | required | The `authorization_code` from step 3. |
| `redirect_uri` | required | Same URI used in step 1. |
| `code_verifier` | required | The original random string used to generate `code_challenge`. |

Example request:

```bash
curl --request POST \
  --url 'https://signin.tradestation.com/oauth/token' \
  --header 'content-type: application/x-www-form-urlencoded' \
  --data 'grant_type=authorization_code' \
  --data 'client_id=YOUR_CLIENT_ID' \
  --data 'code=YOUR_AUTHORIZATION_CODE' \
  --data 'redirect_uri=http://localhost:8080' \
  --data 'code_verifier=5d2309e5bb73b864f989753887fe52f79ce5270395e25862da6940d5'
```

Example response:

```json
{
  "access_token": "eGlhc2xv...MHJMaA",
  "refresh_token": "eGlhc2xv...wGVFPQ",
  "id_token": "vozT2Ix...wGVFPQ",
  "token_type": "Bearer",
  "scope": "openid profile MarketData ReadAccount Trade offline_access",
  "expires_in": 1200
}
```

**Token notes:**

- `access_token` — expires after **20 minutes**. Use the Refresh Token flow to
  renew without re-authentication.
- `id_token` — a JWT containing user profile info. Decode it to extract user
  details. Configurable via scopes (see TradeStation Scopes docs).
- `refresh_token` — present only if `offline_access` was in the requested
  scopes.

## Step-by-Step (Auth0 SDK / Quickstart)

If you use an Auth0 SDK (Swift, Android, SPA, React), the SDK handles
`code_verifier` / `code_challenge` generation automatically.

1. User clicks Login.
2. SDK generates `code_verifier` and derives `code_challenge`.
3. SDK redirects to `/authorize` with the `code_challenge`.
4. Auth0 presents the login and consent prompts.
5. User authenticates; Auth0 stores the `code_challenge` and redirects back
   with a single-use `authorization_code`.
6. SDK posts the `authorization_code` + `code_verifier` to `/oauth/token`.
7. Auth0 verifies that `hash(code_verifier) == code_challenge`.
8. Auth0 returns `id_token`, `access_token`, and optionally a `refresh_token`.
9. Application uses the `access_token` to call the TradeStation API.

**Available Auth0 SDKs that handle PKCE:**

- [Auth0 Swift SDK](https://github.com/auth0/Auth0.swift)
- [Auth0 Android SDK](https://github.com/auth0/Auth0.Android)
- [Auth0 Single-Page-App SDK](https://github.com/auth0/auth0-spa-js)
- [Auth0 React SDK](https://github.com/auth0/auth0-react)
